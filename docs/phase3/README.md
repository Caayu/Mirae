# Phase 3 — professional brush engine

## Pipeline

```
BrushInput (Phase 2: pressure curve, velocity, jitter, stabilizer, interpolator)
  -> arc-length spacing (sample-rate invariant)            [spacing.rs]
  -> per-dab dynamics: base ∘ effectors                    [dynamics/]
  -> scatter (after spacing)                               [scatter.rs]
  -> airbrush time instants (optional)                     [airbrush.rs]
  -> Dab { center, radii, angle, hardness, flow, opacity, texture }
  -> StrokeBuffer: tip coverage × texture -> f32 mask      [tip/, texture.rs, stroke.rs]
       (per-tile parallel for large batches, bit-identical)
  -> paint: premultiplied `over`   erase: destination-out
  -> preview and commit share `paint_over_tile`
```

`tela-brush` still depends only on `color` and `canvas`: no Windows, tablet,
GPU or UI code. The egui panel (`tela-ui`) edits preset data; the renderer
never sees the document.

## Presets

Presets are versioned JSON (`crates/brush/presets/*.json`, embedded at build
time). Example (`chalk.json`, abridged):

```json
{
  "format_version": 1,
  "id": "tela.chalk",
  "name": "Chalk",
  "metadata": { "author": "Tela", "description": "...", "tags": ["chalk"] },
  "tip": { "shape": { "kind": "image", "source": { "kind": "builtin", "name": "charcoal" } } },
  "properties": {
    "size": { "base": 30.0,
              "effectors": [{ "source": { "kind": "pressure" }, "curve": [[0.0, 0.5], [1.0, 1.0]] }] },
    "spacing": { "base": 0.12 },
    "scatter": { "base": 0.08 }
  },
  "scatter": { "mode": "perpendicular", "count": 1, "rotation_jitter": 180.0, "scale_jitter": 0.25 },
  "texture": { "pattern": "chalk", "mode": "height", "scale": 1.0, "contrast": 1.2 }
}
```

Loading: `parse -> read format_version -> migrate step by step -> deserialize
-> validate`. Every struct has `#[serde(default)]`, unknown fields are
ignored, unknown enum variants load as neutral `Unknown`, out-of-range values
are clamped with a warning. Malformed JSON is an error, never a panic. The
`v0 -> v1` migration exists to exercise the path; v0 is an invented draft
format, not a real legacy format.

Built-ins: ink pen, pencil, soft round, marker, airbrush, chalk, calligraphy,
eraser (keys 1–8). Each has a golden sheet in [`corpus/`](corpus/README.md).

## Effectors

Each property (size, opacity, flow, spacing, hardness, angle, aspect,
scatter, texture strength) is

```
v = base
for each enabled effector e:  v = combine_e(v, min_e + (max_e − min_e) · curve_e(input_e))
```

Sources: pressure, speed, tilt magnitude, tilt direction, barrel rotation,
stroke direction, distance (`length` px period), dab index (`period`),
random, smooth noise (`frequency`). Combine modes: multiply, add, replace,
min, max, and `follow` for angles. Curves are monotone cubic
(Fritsch–Carlson). An effector whose input the device lacks is skipped, so
every preset works with a mouse.

**Follow** rotates the running angle toward the source angle by `t ∈ [0,1]`
along the shortest arc. A tip with `n`-fold symmetry (period `P = 360°/n`) is
blended in multiplied-angle space: both angles are mapped to unit vectors at
`θ·360/P`, blended, and mapped back, so a 180°-periodic calligraphy nib never
flips at the wrap. Stroke direction is undefined below 1 px/s (screen);
direction-driven effectors are then neutral instead of reading noise.

**Randomness** is a pure function `(seed, stream, index) -> u64` (no hidden
state), so the re-renderable tail and replays give bit-identical dabs.

## Tips

Evaluated per pixel in dab-local coordinates (rotation, two radii, flips), so
size, aspect, angle and flips work for every shape.

- **Procedural:** round and rectangle with hardness `h`: coverage is 1 inside
  `h·r` and falls off smoothly to 0 at `r`; the falloff is never narrower than
  the anti-aliasing width, so `h = 1` is an anti-aliased edge and lower
  hardness widens it continuously (no jumps, tested).
- **Image:** grayscale coverage with a box-filtered mip pyramid, sampled
  trilinearly with `lod = log2(texels per pixel)`, so a tip looks the same at
  5 px and 500 px. Sources: built-in images generated by code (speckle,
  bristle, charcoal) or an embedded grayscale image in the preset. No external
  assets.

## Textures

A periodic height field sampled in **canvas** space (the paper stays still
under the brush), generated from periodic gradient noise whose lattice
periods divide the texture size, so it is seamless by construction. Patterns:
fine paper, rough paper, chalk. Height `h` (after contrast/brightness) and
strength `s` modulate the dab's opacity ceiling `c`, not its coverage, so the
grain does not wash out with dab overlap or spacing:

| mode | ceiling |
|---|---|
| multiply | `c · (1 − s·(1 − h))` |
| subtract | `max(0, c − s·(1 − h))` |
| height | `c · smoothstep(τ − 0.1, τ + 0.1, h)`, `τ = s·(1 − coverage·c)` |

`height` lets light pressure catch only the paper peaks and heavy pressure
fill the valleys.

## Scatter

Spacing is decided on the unscattered dab, then the dab is displaced
(perpendicular to the path or radially), optionally multiplied into `count`
dabs and given rotation/scale jitter. The number of dabs per unit length
never depends on the scatter amount.

## Airbrush

Time-based deposition at `rate` dabs/s, independent of frame rate:

- Emission instants are `t_k = t₀ + k / rate`, fixed at stroke start; each
  takes its position by interpolating the processed path **in time**. 30 and
  144 fps hosts give identical dab lists (tested).
- While the pen rests, no samples arrive; the host calls `advance_time(now)`
  every frame. Deposition past the last sample is allowed only up to
  `now − lag − HOLD_DELAY` (30 ms), and only if the pen has not moved more
  than the jitter threshold (≥ 0.5 px) since `last_motion`. `lag` is the
  measured delivery latency (`now − sample time`), taking the max of new
  measurements and decaying by ×0.98 per sample. Without this, input
  delivered in late batches made the extrapolated instants pile up at the
  last known point and left beads along fast strokes.
- While moving, time instants that fall within a spacing step of the
  distance-based dabs are skipped, and the distance dabs carry the dwell
  time instead:
  `flow' = 1 − (1 − flow)^min(step / speed · rate, 1)`. `step/speed` is the
  time spent crossing one spacing step, `·rate` the number of time instants
  it represents; the exponent turns per-instant flow into the equivalent
  accumulated flow. Slow strokes therefore deposit more paint per length than
  fast ones, with no beads (local ripple < 2% in tests).

## Eraser

The eraser is the same engine with `compositing.mode = erase`: the stroke
mask is applied as destination-out, `dst' = dst · (1 − m)` on premultiplied
pixels. Preview and commit use the same function (tested). The pen's eraser
end selects the eraser preset automatically (`Tools::for_stroke(device)`); `E`
switches modes for the mouse.

## Performance

`cargo run --release -p tela-corpus --example stamp_bench` — full output in
[stamp_bench.md](stamp_bench.md) (16 hardware threads, this machine).

| brush | 5 px | 25 px | 100 px | 250 px | 500 px |
|---|---:|---:|---:|---:|---:|
| hard round (dabs/s) | 374 593 | 131 767 | 11 050 | 1 907 | 488 |
| soft round | 368 698 | 119 425 | 9 555 | 1 609 | 411 |
| textured | 354 904 | 76 423 | 5 686 | 959 | 243 |
| scatter | 356 799 | 127 903 | 10 840 | 1 897 | 479 |

Large dabs run at ~100–120 Mpx/s untextured and ~60 Mpx/s textured on one
thread. Allocations per dab on the hot path: **0.000** (measured with a
counting global allocator, not assumed). Composition of two layers plus the
stroke overlay: 0.113 ms per 256×256 tile, 0 allocations.

**Single vs parallel** (one input sample per batch, pen at 2000 px/s):

| brush | 100 px | 250 px | 500 px |
|---|---:|---:|---:|
| hard round | 0.99× | 1.70× | 3.24× |
| soft round | 0.99× | 1.70× | 3.16× |
| textured | 1.00× | 1.67× | 2.98× |

Batches are split by tile; each tile is owned by one worker and receives its
dabs in stroke order, so the result is bit-identical to sequential stamping
(tested) with no locks. Below `PARALLEL_MIN_WORK` = 60 000 estimated pixels
the batch stays on one thread, which is why small sizes stay at ~1.0×.

## Limitations

- **No physical tablet was available.** Only a virtual HID device
  ("Microsoft HID RID 000D_0002") is present. All pen evidence comes from
  synthetic Windows Ink injection, which sends integer pixel positions:
  HIMETRIC sub-pixel precision, tilt and barrel rotation were not verified
  visually on real hardware.
- 8-bit layer storage shows banding in very soft, low-flow build-ups.
- The document is limited to the GPU's maximum texture size (no paging of
  the display texture).
- The airbrush rest position is the last processed path point, which lags the
  raw input by one sample.
- `distance` effectors use a fixed period `length`, not the final stroke
  length (unknown while drawing).
- No movement prediction yet; the re-renderable tail allows adding it later.
- The panel is functional, not polished; preset edits are not saved to disk.
