## Current limitations

See [TECHNICAL_DEBT.md](TECHNICAL_DEBT.md) for the full list with
priorities. Most relevant: no physical tablet validation; 8-bit default
storage and 8-bit masks (16-bit documents optional), 8-bit display;
document size bounded by GPU texture size; undo history uncompressed in memory; no
document I/O; preset edits not persisted; UI unpolished.

## Phase 3.5 outcome

Audit and refactors (no new features): workspace metadata and lints,
Ink API without raw handles, smaller brush API, preset hardening, domain
rule moved out of app/UI, golden hygiene, property tests, enforced crate
boundaries, crate/API docs, architecture docs, ADRs, handoff docs, check
script. Details: [CHANGELOG.md](../CHANGELOG.md).

## Phase 4E outcome

16-bit storage per document with the reference observed first (it has no
16-bit documents, no conversion, 8-bit exports; a 16-bit image opens
there with its low byte dropped), parity gate recorded
([parity/4E-16bit.md](parity/4E-16bit.md)); banding measured objectively
(`banding` example and test), memory and speed measured (`depth_bench`:
composition 0.99–1.07×, commit 1.2–1.5×, memory 2×); 8-bit composition
4–23 % faster than at the end of 4D; D12 decided (8-bit default).

## Phase 4D outcome

Masks, clipping and alpha lock with semantics taken from the reference
(observed and measured before implementing: PSD probe of 34 scenarios and
UI operation), parity gate recorded
([parity/4D-masks-clipping-alpha-lock.md](parity/4D-masks-clipping-alpha-lock.md));
the reference's 2 × 2 176 measured swatches kept as a test; preview ==
commit across 126 combinations; 4C composition paths unchanged in
output and speed (`blend_bench`, `stamp_bench`, `history_bench`).

## Phase 4C outcome

Blend modes with the compositing space chosen by measurement against the
reference (sRGB-encoded, not linear light) and the paper taking part in
blending as in the reference; parity gate recorded
([parity/4C-blend.md](parity/4C-blend.md)) with the reference's data
kept as a test. Merge down deferred (TECHNICAL_DEBT #21).

## Phase 4B outcome

Undo/redo with the reference's observed semantics, bit-exact and copy-free
(swap), memory-bounded; parity gate recorded
([parity/4B-undo-redo.md](parity/4B-undo-redo.md)). Undo/redo take
microseconds; recording costs ~0.17 ms per changed painted tile; 256 KiB
per changed tile per step ([performance.md](performance.md)).

## Phase 4A outcome

Layer stack with stable ids and one pixel-mutation path (ADR 0014), layer
panel, parity gate recorded ([PARITY.md](PARITY.md),
[parity/4A-layers.md](parity/4A-layers.md)). Composition cost unchanged
within noise; 0 allocations per dab and per composed tile.
