## Current limitations

See [TECHNICAL_DEBT.md](TECHNICAL_DEBT.md) for the full list with
priorities. Most relevant: no physical tablet validation; 8-bit default
storage and 8-bit masks (16-bit documents optional), 8-bit display;
document size bounded by GPU texture size; undo history uncompressed in memory;
saving and loading synchronous (no autosave, recent files or background
save); transparent export refused for non-Normal stack blending (D-4C-1);
CPU composition single-threaded and linear in layers (TECHNICAL_DEBT #33);
no transparent colour, palette not persisted (debt #35, #36); preset edits
not persisted; UI unpolished.

## Phase 5A outcome

Colour, with the reference observed first (O1–O19: two slots of which
one paints, `X`, integer RGB/HSV, 6-digit hex without alpha, colour
changes outside the history, recent colours from strokes and picks, the
eyedropper on the displayed composite or the layer at the document pixel)
and a parity gate ([parity/5A-color.md](parity/5A-color.md)). `Color`
(opaque, `f32`, no alpha) captured by each stroke with an explicit
`(C·m, m)` rule (ADR 0021); app-owned colour state; a colour panel; the
eyedropper. Matches the reference on the HSV readout, a 51 % coloured
stroke (144,201,234), canvas picks on the probe and the alpha-lock
recolour pixels; the colour-dependent 4C/4D app checks are done
(D-4D-5 closed). Colour costs nothing measurable. Remaining: D-5A-1…8
(no transparent colour, 8-bit layer picks at low alpha, rounding vs
truncation, no wheel/HLS/Lab/CMYK/colour sets, palette not persisted).

## Phase 4G outcome

Integration and hardening, no new features. End-to-end tests drive the
whole stack with real brush strokes (scenarios A–G, a whole drawing
session with an integrated golden, 16 randomized sessions, stress: 300
layers, histories past the step limit, 40 save/load cycles, fully tiled
4096² layers); every measured parity dataset of 4C–4F re-run and passing;
`doc_bench` measures composition against 1–100 layers, realistic 4096²
documents (redraw, stroke frame, save, load), history and memory, and
gates `check.ps1 -Bench` on zero composition allocations; the memory
model is written down ([memory.md](memory.md)). No regression found
against 4E (A/B inside noise). Audit fixes: PNG decoder limit errors
showed nonsense numbers, import refusals were only logged, two
benchmarks' allocators were missing from the `unsafe` inventory. A real
8- and 16-bit session in the running app (mouse and synthetic pen)
passed; Ctrl+Shift+S is taken by another program on the development
machine. Parity record: [parity/4G-integration.md](parity/4G-integration.md).

## Phase 4F outcome

Document I/O with the reference's file workflow and PNG fidelity observed
first (a corrupt PNG crashed it), parity gate recorded
([parity/4F-file-workflow.md](parity/4F-file-workflow.md)): the `.mirae`
v1 format (ADR 0019, [formats/mirae-v1.md](formats/mirae-v1.md)) and the
`tela-io` crate (ADR 0020); bit-exact save/load at both depths, atomic
save, explicit limits, strict versioning, corruption and property tests,
v1 fixtures as a compatibility contract; PNG export equal to the
reference's with the paper; PNG import that keeps 16 bits or rounds
(deliberately unlike the reference's truncation); the desktop workflow
with native dialogs, drag-and-drop, a revision-based save point and the
unsaved-changes prompt. Save/load measured (`io_bench`): 640 MiB of 8-bit
pixels in 1.9 s / 0.7 s with 2–3 MiB of extra memory.

## Phase 4E outcome

16-bit storage per document with the reference observed first (it has no
16-bit documents, no conversion, 8-bit exports; a 16-bit image opens
there with its low byte dropped), parity gate recorded
([parity/4E-16bit.md](parity/4E-16bit.md)); banding measured objectively
(`banding` example and test), memory and speed measured (`depth_bench`:
composition 0.99–1.07×, commit 1.2–1.5×, memory 2×); 8-bit composition
4–23 % faster than at the end of 4D; D12 decided (8-bit default).

## Phase 4B outcome

Undo/redo with the reference's observed semantics, bit-exact and copy-free
(swap), memory-bounded; parity gate recorded
([parity/4B-undo-redo.md](parity/4B-undo-redo.md)). Undo/redo take
microseconds; recording costs ~0.17 ms per changed painted tile; 256 KiB
per changed tile per step ([performance.md](performance.md)).

within noise; 0 allocations per dab and per composed tile.
